# SpotifyToHomePod

Play Spotify from any phone to synced HomePods. A bridged Lima VM on an
always-on Mac runs librespot (Spotify Connect endpoint, zeroconf -- no
credentials stored) feeding OwnTone, which streams AirPlay 2 to the
HomePods with multi-room sync. The player's phone is only a remote:
audio streams from Spotify's servers to the VM directly.

## Architecture

    Phone (Spotify app, Premium)
      | mDNS discovery + session authorization (zeroconf, nothing stored)
      v
    Lima VM, bridged onto the LAN (QEMU + socket_vmnet)
      raspotify/librespot --backend pipe --> /srv/music/spotify (fifo)
      OwnTone (official container, host network) reads the fifo
      | AirPlay 2, synced
      v
    HomePods / Apple TV / any AirPlay speaker

- Bridged networking is mandatory: mDNS multicast must reach the LAN in
  both directions (phone -> librespot, OwnTone -> speakers).
- vz cannot do this: its native bridged mode needs the Apple-granted
  `com.apple.vm.networking` entitlement, and it cannot attach to
  socket_vmnet's bridged socket. Hence `vmType: qemu`.

## Components

| Piece | Where | Source |
|---|---|---|
| limactl 2.1.1 | `./result-lima` | nixpkgs (flake) |
| qemu | `./result-qemu` | nixpkgs (flake) |
| socket_vmnet 1.2.2 | `/opt/socket_vmnet` | built by flake (not in nixpkgs) |

| Guest provisioning | `provision.sh` (mirror of template block) | this repo |

## State outside this repo

- `/opt/socket_vmnet/bin/{socket_vmnet,socket_vmnet_client}` -- copied
  from `result-socket_vmnet` (root-owned; Lima refuses Nix store paths
  because /nix/store is group-writable by nixbld).
- `/etc/sudoers.d/lima` (mode 444) -- generated by `./lima sudoers`,
  scoped to the exact socket_vmnet invocation plus its pkill. Regenerate
  and reinstall after changing `.lima/_config/networks.yaml` or
  rebuilding socket_vmnet.
- UniFi: "Multicast DNS" reflection enabled between the guest network
  and the LAN; guest isolation off.

## Operate

    ./lima start spotifytohomepod    # start (e.g. after Mac reboot)
    ./lima stop spotifytohomepod     # stop
    ./lima shell spotifytohomepod    # shell inside guest

- Web UI (speaker selection, per-speaker volume): http://<vm-ip>:3689
  (VM gets its address from the router via DHCP; find it with
  `./lima shell spotifytohomepod ip -4 addr show dev lima0`).
- The phone picks the device named "HomePods" in Spotify's device list.
  Premium is required on the playing account (librespot limitation).
- Track metadata does not show in OwnTone's UI yet; the phone's Spotify
  app shows it as usual. librespot does not write a metadata pipe itself,
  but it does report every track over `--onevent`, and
  `bridge/librespot-metadata` turns those events into the Shairport-format
  metadata pipe OwnTone reads. Not yet wired into this VM: add
  `LIBRESPOT_ONEVENT` to `/etc/raspotify/conf` and create
  `/srv/music/spotify.metadata` to turn it on.

## Rebuild from scratch

    nix build .#socket_vmnet -o result-socket_vmnet
    nix build .#lima -o result-lima
    nix build .#qemu -o result-qemu
    # install socket_vmnet + sudoers (see "State outside this repo")
    ./lima start ./spotifytohomepod.yaml --name=spotifytohomepod --tty=false

To reprovision a live guest after editing `provision.sh`:

    ./lima copy provision.sh spotifytohomepod:/tmp/provision.sh
    ./lima shell spotifytohomepod sudo bash /tmp/provision.sh
